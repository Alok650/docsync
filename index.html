View on GitHub API reference
$ npx @dev_ap/docsync init

How it works

Step 1

Diff changed symbols

Tree-sitter parses your TypeScript, JavaScript, or Python and finds exactly which functions and classes changed — not just which lines.

Step 2

Look up doc sections

A sharded index maps every symbol to its documentation. Changed symbols are resolved to the exact markdown heading that describes them.

Step 3

Generate an update

An LLM sees the before and after source alongside the current doc body, and produces a minimal, accurate update to the affected paragraph.

Step 4

Post a PR comment

One comment per PR, updated on each push. Review the diff inline, apply with /docsync apply, or dismiss it.

Commands

docsync generate

Generate initial API docs, llms.txt, and context7.json from your source code using an LLM. Run once to bootstrap documentation for a new repo.

docsync init

Scan your codebase and docs, write the symbol index under .autodocs/, and generate the GitHub Actions workflow file.

docsync check

Diff the current branch, find outdated doc sections, and post a PR comment. Add --dry-run to preview locally without posting.

docsync symbols <file>

List all public symbols extracted from a source file. Useful for verifying docsync can parse your code.

Drop into any repo in two minutes

# 1. Generate initial docs (new repos)
npx @dev_ap/docsync generate

# 2. Create the index + workflow
npx @dev_ap/docsync init

# 3. Commit everything docsync created
git add .autodocs/ .github/workflows/docsync.yml
git commit -m "chore: add docsync"

# 4. Add your API key to GitHub → Settings → Secrets
#    ANTHROPIC_API_KEY  or  OPENAI_API_KEY
