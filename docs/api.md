# API Reference

> Generated by DocSync on 2026-05-04. Updated automatically on every PR via [DocSync](https://github.com/Alok650/docsync).

### `src/agent/doc-generate-agent.ts`

#### DocGenerateRequest
*interface*

Represents a request to generate documentation for a single code symbol. It carries the symbol's name, its kind (such as function, class, or interface), the file path where it is defined, and the full source text of the symbol.

#### DocGenerateAgent
*class*

Wraps an `LLMClient` to generate documentation for a given code symbol. Accepts a `DocGenerateRequest` in `generateDoc`, constructs a prompted completion request using a system prompt, a user prompt built from the request, and a configured token limit, then returns the model's response as a `Promise<string>`.

### `src/agent/doc-update-agent.ts`

#### DocUpdateRequest
*interface*

Represents a request to update documentation for a specific code symbol. Carries the symbol name, the file path where it resides, the code before and after a change, and the target `DocSection` to be updated.

#### DocUpdateAgent
*class*

Wraps an LLM client to generate updated documentation text from a given `DocUpdateRequest`. Accepts an `LLMClient` and a model identifier string at construction, then exposes `generateUpdate`, which builds a user prompt from the request and calls the client with a fixed system prompt and token limit, returning a promise that resolves to the generated documentation string.

### `src/agent/generate-prompts.ts`

#### GENERATE_SYSTEM_PROMPT
*variable*

A string constant that defines the system prompt used to configure the DocSync AI documentation-writing agent. It instructs the model to produce concise, one-to-three sentence prose descriptions of code symbols based solely on their provided source code, covering functions, classes, interfaces, types, variables, and enums while adhering to strict rules about tone, format, and factual accuracy.

#### buildGenerateUserPrompt
*function*

Builds a user prompt string for requesting documentation of a given code symbol, accepting an options object containing the symbol name, its kind, the file path, and the source code text. Returns a formatted string that instructs the documentation writer to produce a plain prose description, embedding the symbol name, kind, file, and source code directly into the prompt.

### `src/agent/prompts.ts`

#### SYSTEM_PROMPT
*variable*

A string constant containing the system prompt used to configure the DocSync documentation-editing agent. It defines the agent's role, the inputs it receives (before/after source code and an existing documentation section), the output it should produce (updated paragraph text only), and a set of rules governing how changes should be scoped, how the author's voice should be preserved, and how unsupported claims should be avoided.

#### buildUserPrompt
*function*

Accepts a `PromptContext` containing a symbol name, file path, before-and-after code snapshots, and an existing documentation section, then builds and returns a formatted prompt string instructing a model to produce updated documentation body text for that section. The returned string presents the code diff and current documentation within labeled XML-style tags and directs the model to output only the replacement body with no headings or explanation.

### `src/config.ts`

#### LLM_PROVIDER
*variable*

A read-only constant object enumerating the supported LLM provider identifiers, mapping `ANTHROPIC` to the string `'anthropic'` and `OPENAI` to the string `'openai'`. These values serve as standardized keys for identifying which language model provider is in use throughout the library.

#### LLMProvider
*type*

Represents a union type of all valid LLM provider values, derived from the `LLM_PROVIDER` constant object by extracting the type of each of its values. This ensures that any variable of type `LLMProvider` is constrained to one of the predefined provider strings defined in `LLM_PROVIDER`.

#### LLMConfig
*interface*

Represents the configuration required to specify a language model. It holds a `provider` field identifying the LLM provider and a `model` field specifying the model name, both of which are read-only.

#### DocSyncConfig
*interface*

Represents the top-level configuration for DocSync, grouping the paths and model settings needed to run the tool. `docs` specifies the path to the documentation files, `code` specifies the path to the source code, and `llm` holds the language model configuration used for generating descriptions.

#### loadConfig
*function*

Reads and parses the `docsync.json` configuration file from the given working directory, defaulting to `process.cwd()` if none is provided. Returns a fully merged `DocSyncConfig` by combining default values with any fields found in the file, with `llm` sub-options merged independently. If the file is missing or cannot be parsed, it logs a warning (on parse failure) and returns the default configuration.

### `src/constants.ts`

*variable*

The name of the hidden directory, `.autodocs`, used as the root folder where AutoDocs stores its generated files and configuration.

#### MAP_FILENAME
*variable*

The name of the map file used by the library, fixed to the value `'map.json'`.

#### MAP_RELATIVE_PATH
*variable*

Stores the full relative path to the map file by joining `AUTODOCS_DIR` and `MAP_FILENAME` with a path separator.

#### LOOKUP_DIR
*variable*

Path string pointing to the `lookup` subdirectory within `AUTODOCS_DIR`, used to locate or store lookup-related files for the autodocs system.

#### WORKFLOW_DIR
*variable*

Exported constant that holds the relative path string `'.github/workflows'`, representing the directory where GitHub Actions workflow files are stored within a repository.

#### WORKFLOW_FILENAME
*variable*

The name of the workflow configuration file used by DocSync, set to `docsync.yml`.

#### CONFIG_FILENAME
*variable*

The name of the configuration file that DocSync looks for, set to `docsync.config.json`.

### `src/defaults.ts`

#### BM25
*variable*

Default configuration constants for the BM25 ranking algorithm, exported as a readonly object. Contains `K1` (term frequency saturation, set to 1.5), `B` (document length normalization, set to 0.75), `CORPUS_MIN_SCORE` (the minimum BM25 score required to include a candidate in corpus-level search results), and `MATCH_MIN_SCORE` (the minimum score required to map a document section to a symbol).

#### AI
*variable*

A frozen configuration object holding default AI provider settings used when no `autodocs.config.json` is present. It specifies `'anthropic'` as the default provider, `'claude-sonnet-4-6'` as the default model, and caps model response output at `1024` tokens per documentation-update request.

#### GIT
*variable*

Holds default configuration constants for Git operations, exposing `DEFAULT_BASE_REF` as the base branch (`'origin/main'`) used when computing a `git diff` during CI, which can be overridden via `GitHubContext.baseRef`.

#### GITHUB
*variable*

Constant object holding default configuration values for GitHub API interactions, frozen at declaration time via `as const`. Its sole property, `COMMENTS_PER_PAGE`, sets the page size to 100 when paginating pull request comments to locate an existing AutoDocs comment.

#### LOOKUP
*variable*

Immutable configuration object that controls the lookup table's sharding and fingerprinting behavior. `SHARD_NIBBLES` defines the number of leading hex characters taken from a symbol name's SHA-256 hash to determine its shard (defaulting to `2`, yielding 256 shards), while `FINGERPRINT_HEX` defines the number of hex characters stored as a symbol's content fingerprint (defaulting to `16`, producing a 64-bit fingerprint).

#### CLI
*variable*

Defines compile-time constant configuration values for the CLI interface. Currently exposes `SYMBOL_COLUMN_WIDTH`, a numeric constant set to `30` that controls the column width for symbol names in the `autodocs symbols` output table.

#### GENERATE
*variable*

Configuration constants controlling the documentation generation pipeline, exported as a readonly object. `CONCURRENCY` caps the number of parallel LLM calls during symbol documentation generation, `DEFAULT_OUT` specifies the default output path for the generated API docs relative to the current working directory, and `MAX_TOKENS` sets the maximum token budget allowed for initial doc generation.

### `src/differ/ast-differ.ts`

#### SymbolWithText
*interface*

Extends `ExtractedSymbol` by adding a `text` property that holds the raw source text of the symbol.

#### parseSymbolsWithText
*function*

Parses a source file string and its file path into an array of `SymbolWithText` objects, each enriched with the raw source text extracted from the corresponding line range. Resolves the programming language from the file path, builds a syntax tree using the appropriate parser, extracts symbols via `parseSymbols`, and returns an empty array if the language cannot be determined.

#### diffSymbols
*function*

Compares two versions of a source file's symbols by parsing both the `before` and `after` source strings using the provided `filePath`, then returns a `Promise` resolving to an array of `SymbolChange` objects. Each entry indicates whether a symbol was `added`, `modified` (when its text differs between versions), or `removed` based on a name-keyed comparison of the two parsed symbol sets.

### `src/differ/git-differ.ts`

#### parseGitDiff
*function*

Parses the raw string output of a `git diff` command and returns an array of `ChangedFile` objects, each containing the file path and its changed line ranges. For each file header encountered, a new entry is created; for each hunk header, the starting line and count are used to compute a `[start, end]` tuple that is appended to that file's `changedLines` array. When a hunk specifies a count of zero, the start line is used as both the start and end of the range.

#### getGitDiff
*function*

Runs `git diff` between the specified `base` ref and `HEAD` within `repoDir`, excluding the auto-generated docs directory from the comparison, and returns the parsed result as an array of `ChangedFile` objects. Accepts the repository directory path and an optional base ref that defaults to `GIT.DEFAULT_BASE_REF`. The raw diff output is passed to `parseGitDiff` to produce the structured return value.

#### getBeforeContent
*function*

Retrieves the file contents at a given Git ref by running `git show` in the specified repository directory. Accepts a `repoDir` path, a relative `filePath`, and an optional `base` ref that defaults to `GIT.DEFAULT_BASE_REF`. Returns the file's content as a UTF-8 string, or an empty string if the command fails.

### `src/differ/types.ts`

#### ChangeType
*type*

Represents the classification of a single change detected during a diff operation, with possible values of `'added'` for new entries, `'removed'` for deleted entries, and `'modified'` for entries that have been altered.

#### SymbolChange
*interface*

Represents a single detected change to a code symbol, capturing the kind of change via `type`, the name of the affected symbol via `symbol`, and the source file where the symbol resides via `file`. All properties are read-only.

#### ChangedFile
*interface*

Represents a file that has been modified, pairing the file's path with the line ranges affected by the changes. The `file` property holds the path to the changed file, and `changedLines` contains an array of `[start, end]` line number tuples identifying each changed range within that file. Both properties are read-only.

### `src/editor/markdown-editor.ts`

#### MarkdownEditor
*class*

Provides static utilities for manipulating Markdown documents. Its `replaceSection` method accepts a Markdown `source` string, a `sectionHeading` to locate, and a `newBody` string to substitute, parsing the document into an AST to find the target heading and replace all content between it and the next heading of equal or lesser depth. Returns the updated Markdown document as a string, or the original `source` unchanged if the specified heading is not found.

### `src/extractor/constants.ts`

#### LANGUAGE
*variable*

A constant object enumerating the supported programming languages, with string values for `TYPESCRIPT`, `JAVASCRIPT`, and `PYTHON`. The `as const` assertion makes all values deeply readonly and preserves their literal types.

#### Language
*type*

Represents a union type of all valid language values defined in the `LANGUAGE` constant object, derived by indexing into `LANGUAGE` with all of its own keys.

#### SYMBOL_KIND
*variable*

A constant object that enumerates the supported symbol kind identifiers used throughout the extractor, mapping named keys such as `FUNCTION`, `CLASS`, `METHOD`, `INTERFACE`, `TYPE`, and `VARIABLE` to their corresponding lowercase string values. Declared with `as const` to ensure the values are treated as literal types rather than general strings.

#### SymbolKind
*type*

Represents the union of all possible symbol kind values derived from the `SYMBOL_KIND` constant object. It is a type alias that constrains values to only those defined as properties of `SYMBOL_KIND`, such as `"function"`, `"class"`, `"interface"`, `"type"`, `"variable"`, or `"enum"`.

### `src/extractor/index.ts`

#### resolveLanguage
*function*

Accepts a file path string and derives its extension (lowercased) to look up the corresponding `Language` value in `EXTENSION_LANGUAGE_MAP`. Returns the matched `Language` if the extension is recognized, or `null` if no mapping exists.

#### parseSymbols
*function*

Accepts a parsed syntax tree, a file path, and a target language, then dispatches to the appropriate language-specific extractor to retrieve all symbols defined in the source file. Returns an array of `ExtractedSymbol` objects for TypeScript, JavaScript, or Python based on the provided `language` value.

#### extractSymbols
*function*

Accepts a file path, reads the file's source code, and parses it into a syntax tree using the resolved language and corresponding parser. Returns a promise that resolves to an array of `ExtractedSymbol` objects extracted from the parsed tree, or an empty array if the language cannot be resolved or the tree cannot be produced.

### `src/extractor/languages/node-types.ts`

#### TS_NODE
*variable*

A constant object mapping semantic labels to their corresponding TypeScript syntax node type strings as used by a tree-sitter parser. Each key provides a readable identifier for a common TypeScript construct — such as `FUNCTION_DECLARATION`, `CLASS_DECLARATION`, or `INTERFACE_DECLARATION` — while its value holds the exact node type string expected by the parser. Declared `as const` to ensure all values are treated as literal types throughout the codebase.

#### PY_NODE
*variable*

A constant object representing Python AST node type identifiers, providing named string literals for `function_definition` and `class_definition` node kinds used when traversing or inspecting a Python syntax tree.

### `src/extractor/languages/python.ts`

#### extractPythonSymbols
*function*

Traverses the top-level children of a parsed Python syntax tree and extracts function and class definitions as `ExtractedSymbol` instances. Accepts a `Tree` representing the parsed source and a `file` path string used when constructing each symbol. Returns an array of successfully created `ExtractedSymbol` objects, omitting any nodes for which symbol creation fails.

### `src/extractor/languages/typescript.ts`

#### extractTypeScriptSymbols
*function*

Traverses the root-level children of a parsed TypeScript syntax tree and extracts all exported symbol declarations, returning an array of `ExtractedSymbol` objects. Accepts a Tree-sitter `Tree`, the source file path, and a `Language` instance, then filters nodes to those matching known declaration types, resolving variable declarators individually when needed. Each discovered symbol is built via `makeSymbol` using the declaration's name, inferred kind, file path, full export node, and language.

### `src/extractor/loader.ts`

#### getParser
*function*

Accepts a `Language` identifier and asynchronously returns a `Parser` instance configured for that language. Initializes the underlying WebAssembly runtime on first call, then loads the corresponding WASM language file from a predefined path map, constructs and configures a new `Parser`, and caches it so subsequent calls for the same language return the cached instance directly.

### `src/extractor/types.ts`

#### ExtractedSymbol
*interface*

Represents a single code symbol extracted from a source file, capturing its `name`, `kind` (such as function, class, or interface), the `file` path where it resides, the `startLine` and `endLine` of its definition, and the `language` it is written in. All properties are read-only.

### `src/generator/index.ts`

#### GenerateResult
*interface*

Represents the result of a documentation generation operation. Contains the total number of symbols processed (`symbolCount`), the number of files generated (`fileCount`), and the output directory path where the generated files were written (`outPath`). All fields are read-only.

#### GenerateOptions
*interface*

Represents the configuration options required to run the documentation generation process. It specifies the source code directory (`codeDir`), the output file path (`outPath`), the repository root (`repoDir`), and project metadata including `projectTitle` and `projectDescription`. It also requires an `LLMClient` instance and a `model` identifier for the language model, with an optional `concurrency` value to control parallel processing.

#### generateDocs
*function*

Accepts a `GenerateOptions` object and orchestrates the full documentation generation pipeline: discovers code files under `opts.codeDir`, parses their exported symbols, generates prose descriptions for each symbol via `DocGenerateAgent` with configurable concurrency, and renders the results as Markdown written to `opts.outPath` alongside `llms.txt` and a Context7 JSON file. Returns a `GenerateResult` containing the total number of documented symbols, the number of files processed, and the output path.

### `src/github/client.ts`

#### createOctokit
*function*

Accepts a `GitHubContext` object and returns a new `Octokit` instance authenticated with the provided token. If a `baseUrl` is present on the context, it is passed to the `Octokit` constructor to support GitHub Enterprise or custom API endpoints.

### `src/github/context.ts`

#### readGitHubContext
*function*

Reads GitHub context from environment variables (`GITHUB_TOKEN`, `GITHUB_REPOSITORY`, `PR_NUMBER` or `GITHUB_PR_NUMBER`) and returns a `GitHubContext` object containing the parsed owner, repo, pull request number, base ref, token, and optional API base URL. If any of the required variables are missing or `GITHUB_REPOSITORY` cannot be split into a valid owner and repo, the function returns `null`. The base ref is resolved by calling `readEventBaseSha()`, falling back to `GITHUB_BASE_REF`, and finally defaulting to `'main'`.

### `src/github/pr-comment.ts`

#### GitHubOutput
*class*

Manages posting and updating documentation update comments on a GitHub pull request using an `Octokit` client and a `GitHubContext`. Its `postOrUpdate` method renders the provided `ProposedDocUpdate` array into a comment body and either creates a new PR comment, updates the first existing bot-authored comment (identified by a `COMMENT_MARKER`), or deletes any duplicates beyond the first. The private `findExistingComments` method paginates through all PR comments and filters for those containing the marker.

### `src/github/types.ts`

#### GitHubContext
*interface*

Represents the contextual information required to interact with a GitHub pull request. Holds the repository `owner` and `repo` name, the `prNumber` identifying the pull request, the `baseRef` branch name, and an authentication `token`. Optionally accepts a `baseUrl` to support GitHub Enterprise or other custom API endpoints.

#### ProposedDocUpdate
*interface*

Represents a proposed update to a documentation file, capturing the target `docFile` and `section` to be modified, the original `beforeBody` content alongside the replacement `afterBody` content, and the `symbolName` and `symbolFile` identifying the source code symbol that prompted the change.

### `src/github/workflow-generator.ts`

#### generateWorkflow
*function*

Generates a GitHub Actions workflow file inside the specified repository directory by creating the necessary workflow subdirectory (recursively) and writing the workflow content to a file. Accepts `repoDir` as the path to the root of the repository. Returns a promise that resolves to the full file path of the generated workflow file.

### `src/llm/anthropic.ts`

#### AnthropicClient
*class*

Wraps the Anthropic SDK to implement the `LLMClient` interface, accepting an optional API key during construction. Its `complete` method sends a message request to the specified Anthropic model using the provided options — including model name, max tokens, an optional system prompt, and a message array — then extracts and returns the trimmed text from the first text content block in the response. Throws an error if the response contains no text content block.

### `src/llm/factory.ts`

#### createLLMClient
*function*

Accepts a `DocSyncConfig` object and returns the appropriate `LLMClient` implementation based on the configured provider, instantiating either an `AnthropicClient` or an `OpenAIClient`. Throws an error if the specified provider is not supported.

### `src/llm/openai.ts`

#### OpenAIClient
*class*

Wraps the OpenAI SDK to implement the `LLMClient` interface, accepting an optional `apiKey` at construction to initialize the underlying client. Its `complete` method accepts an `LLMCompletionOptions` object — optionally prepending a system message — and sends a chat completion request to the specified model, returning the trimmed text content of the first response choice. Throws an error if the response contains no text content.

### `src/llm/types.ts`

#### LLMMessage
*interface*

Represents a single message in a conversation with a language model, capturing the sender's role and the message text. The `role` field identifies whether the message originates from the `'user'` or the `'assistant'`, while `content` holds the plain-text body of the message. Both fields are read-only, making instances immutable after creation.

#### LLMCompletionOptions
*interface*

Represents the configuration options required to request a completion from a language model. It specifies the target `model`, an optional `system` prompt, an ordered list of `messages` forming the conversation history, and a `maxTokens` limit controlling the maximum length of the generated response.

#### LLMClient
*interface*

Represents a client capable of interacting with a language model. Exposes a single `complete` method that accepts an `LLMCompletionOptions` object and returns a `Promise` resolving to the generated text string.

### `src/logger.ts`

#### logger
*variable*

A pre-configured Consola logger instance exported for use throughout the library. Sets the log level to `4` (debug) when the `DOCSYNC_DEBUG` environment variable is defined, and defaults to `3` (info) otherwise.

### `src/map/builder.ts`

#### buildMap
*function*

Accepts an array of code file paths, a documentation directory path, and an optional root directory (defaulting to `process.cwd()`), then concurrently scans the documentation for sections and extracts symbols from each code file. For each symbol, it uses a BM25 matcher to find relevant documentation sections and builds a `MapEntry` with relative file paths and matched doc references. Returns a `Promise` resolving to a `MapFile` object containing a version number and the complete array of symbol-to-documentation mappings.

### `src/map/lookup.ts`

#### symbolShard
*function*

Accepts a symbol name string and returns a short hexadecimal shard key by computing its SHA-256 hash and taking the first `LOOKUP.SHARD_NIBBLES` characters of the resulting hex digest.

#### computeFingerprint
*function*

Accepts a `text` string and returns a truncated SHA-256 hex digest of it, with the output length determined by `LOOKUP.FINGERPRINT_HEX`.

#### buildShards
*function*

Accepts a `MapFile` and partitions its mappings into a `Map` of `LookupTable` objects keyed by shard identifier, where each shard is determined by calling `symbolShard` on the entry's symbol. Entries with no associated docs are skipped, and multiple `DocRef` arrays for the same symbol within a shard are merged together. Returns the resulting `Map<string, LookupTable>` of sharded lookup tables.

#### buildLookup
*function*

Accepts a `MapFile` and builds a flat `LookupTable` by iterating over all shards produced by `buildShards`, merging the `DocRef` arrays for each symbol across shards. Returns a `Record<string, DocRef[]>` where each key is a symbol name mapped to its combined list of documentation references.

#### readLookupForSymbols
*function*

Reads the lookup table entries relevant to a given set of symbol names by loading only the shard files that contain those symbols from the repository's lookup directory. Accepts a repository root path and a readonly array of symbol name strings, then resolves the shard IDs for each symbol and reads the corresponding JSON shard files in parallel, silently skipping any shards that cannot be read. Returns a `LookupTable` composed of all entries found across the loaded shards.

### `src/map/types.ts`

#### DocRef
*interface*

Represents a reference to a specific location within a documentation source. Holds the `file` path, a `section` identifier, and a `lines` tuple marking the inclusive start and end line numbers of the referenced content.

#### MapEntry
*interface*

Represents a single entry in the documentation map, associating a named symbol with its source file and a list of documentation references. Optionally includes a `fingerprint` field — a 16-character SHA-256 prefix of the symbol's source text — which the updater uses to skip re-mapping symbols whose source has not changed.

#### MapFile
*interface*

Represents the structure of a map file, consisting of a fixed `version` field locked to the literal value `1` and a read-only array of `MapEntry` objects stored in `mappings`. Both properties are immutable, preventing modification after the object is created.

#### LookupTable
*type*

A read-only mapping from string keys to read-only arrays of `DocRef` values, used to associate identifiers or tokens with their corresponding document references. Both the top-level record and each array it contains are immutable, preventing modification after creation.

#### toDocSection
*function*

Accepts a `DocRef` and a `body` string, and constructs a `DocSection` object by combining the file path, section heading, and line range from the `DocRef` with the provided body content. Returns the resulting `DocSection`.

### `src/map/updater.ts`

#### updateMapForChangedFiles
*function*

Reads an existing map file from `mapFilePath`, then iterates over each file path in `changedFiles` to re-extract its symbols, computing a new fingerprint for each. For symbols whose source is unchanged (matching fingerprint), existing doc mappings are preserved; for new or modified symbols, prior docs are carried forward as potentially stale entries pending a full re-mapping pass. Writes the updated map back to disk and returns the resulting `MapFile`.

### `src/map/writer.ts`

#### writeMapFile
*function*

Writes a `MapFile` to disk at the specified `filePath` and simultaneously writes its sharded lookup data as individual JSON files into a `LOOKUP_DIR` subdirectory alongside the map file, creating that directory if it does not exist. All writes are performed atomically and in parallel using `Promise.all`. Returns a `Promise<void>` that resolves when all files have been successfully written.

### `src/pipeline/check.ts`

#### CheckResult
*interface*

Represents the outcome of a documentation check, containing two read-only collections: `updates`, which holds the set of proposed documentation updates, and `skippedFiles`, which lists file paths that were present in the diff but could not be read due to deletion, permission errors, or similar issues.

#### runCheck
*function*

Accepts a `GitHubContext`, a `DocSyncConfig`, and an optional repository directory path (defaulting to the current working directory), and returns a `Promise<CheckResult>` containing any documentation updates and skipped files. It collects changed files relative to the provided base ref and, if changes are found, generates documentation updates for them. If no changes are detected, it returns early with an empty updates array and the list of skipped files.

### `src/retrieval/bm25-retriever.ts`

#### BM25Retriever
*class*

Implements the `RetrievalAdapter` interface using BM25-based text matching to retrieve relevant documentation references for a given symbol change. Constructed with a collection of `DocSection` objects, it initializes an internal `BM25Matcher` that is queried in `retrieve` against the changed symbol's name. Returns a resolved `Promise` containing only the `DocRef` entries whose BM25 scores meet or exceed the minimum threshold, each carrying the source file, section heading, and line range of the matched documentation section.

### `src/retrieval/index.ts`

#### TieredRetriever
*class*

Orchestrates document retrieval across two prioritized `RetrievalAdapter` instances, querying the primary tier first and falling back to the secondary tier only when the first yields no results. The `retrieve` method accepts a `SymbolChange` and returns a `RetrievalResult` tagged with the tier that produced the documents. The `retrieveAll` method processes a collection of `SymbolChange` entries in parallel and returns only those results that contain at least one document.

### `src/retrieval/structural.ts`

#### StructuralRetriever
*class*

Implements the `RetrievalAdapter` interface by performing fast, index-based lookup of documentation references keyed on symbol names. Accepts a `LookupTable` at construction time, converting it into an internal `Map` for efficient access. The `retrieve` method accepts a `SymbolChange` and returns a resolved `Promise` containing the array of `DocRef` entries associated with the changed symbol, or an empty array if no match is found.

### `src/retrieval/types.ts`

#### RetrievalResult
*interface*

Represents the outcome of a documentation retrieval operation, capturing the symbol change that was looked up, the associated documentation references, and the tier indicating how the result was found — `1` for a structural index match via `map.json` or `2` for a BM25 fallback match.

#### RetrievalAdapter
*interface*

Represents a contract for objects that can fetch documentation references in response to a symbol change. Requires a single `retrieve` method that accepts a `SymbolChange` and returns a `Promise` resolving to a readonly array of `DocRef` objects.

### `src/scanner/bm25.ts`

#### BM25Result
*interface*

Represents a single result from a BM25 search query, pairing a `DocSection` with its computed relevance `score`. Both properties are read-only, ensuring the result cannot be mutated after creation.

#### BM25Matcher
*class*

Implements BM25 relevance ranking over a collection of `DocSection` objects, precomputing per-document term frequencies, inverse document frequencies, and average document length at construction time. The `query` method accepts a symbol name, tokenizes it, scores each section using the BM25 formula with constants `K1` and `B`, and returns an array of `BM25Result` objects filtered above a minimum score threshold and sorted by descending relevance.

### `src/scanner/doc-scanner.ts`

#### DocSection
*interface*

Represents a discrete section of documentation extracted from a source file, identified by its `heading` and `body` text. Captures the source `file` path along with the `startLine` and `endLine` positions indicating where the section appears within that file.

#### extractSectionBody
*function*

Searches a Markdown `content` string for a section matching `sectionHeading` (ignoring heading prefix characters) and returns the trimmed body text that follows it, stopping at any subsequent heading of equal or lesser depth. Returns `null` if the heading is not found or the body is empty.

#### scanDocs
*function*

Accepts a directory path `docsDir`, recursively discovers documentation files within it using `findDocFiles`, and reads and parses each file into structured sections. Returns a promise that resolves to a flattened array of `DocSection` objects extracted from all discovered files.

### `src/scanner/file-finder.ts`

#### CODE_EXTENSIONS
*variable*

A read-only set of file extensions identifying supported source code file types, including TypeScript (`.ts`, `.tsx`), JavaScript (`.js`, `.jsx`, `.mjs`, `.cjs`), and Python (`.py`) variants.

#### DOC_EXTENSIONS
*variable*

A read-only set of file extensions recognized as documentation files, containing `'.md'` and `'.mdx'`.

#### findCodeFiles
*function*

Searches the specified directory `dir` recursively for files matching recognized code extensions, delegating to `findFiles` with the predefined `CODE_EXTENSIONS` filter. Returns a promise that resolves to an array of matching file path strings.

#### findDocFiles
*function*

Searches the specified directory for documentation files matching the supported `DOC_EXTENSIONS` file types and returns a promise that resolves to an array of matching file paths.
